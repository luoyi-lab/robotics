## 📅 每日安排

### Day 1 · 周一 11/16 · 拉格朗日动力学：单摆

**学**
- **为什么需要动力学**：FK/IK 只管「在哪」，PID 只管「去」，**但力矩该给多少？**
  - 单摆：`τ = m·l²·θ̈ + m·g·l·sinθ`
  - 重力项 + 惯性项 —— 这就是「前馈」的来源
- **拉格朗日法两步**：
  1. 写动能 `T` 和势能 `V`
  2. `L = T - V`，代入 `d/dt(∂L/∂q̇) - ∂L/∂q = τ`

**必须写出来**
- `day1_lagrange_pendulum.py`
  - 手推 `τ = m·l²·θ̈ + m·g·l·sinθ`，写在注释里
  - 数值验证：给定 `τ(t)`，用 RK4 或欧拉积分跑出 `θ(t)`，和解析小角度解对比

**验证**
- [ ] 小角度（θ < 0.1 rad）时，仿真周期 ≈ `2π√(l/g)`
- [ ] 大角度（θ = 1.5 rad）时，周期明显变长（**这就是非线性**）

**力扣**：144 二叉树的前序遍历（递归 + 迭代都要写）

### Day 2 · 周二 11/17（实际 11/18 周三完成）· 状态空间 + 连续→离散 ✅

**学**
- **状态空间**：`ẋ = Ax + Bu`，`y = Cx + Du`
  - 单摆：`x = [θ, θ̇]ᵀ`，`A = [[0,1],[−g/l,0]]`（小角度线性化）
- **连续 → 离散**（零阶保持）：
  - 简单：`x[k+1] = x[k] + dt·(Ax[k] + Bu[k])`（前向欧拉）
  - 标准：`Ad = e^{A·dt}`，`Bd = ∫e^{Aτ}dτ·B`
- **为什么要离散**：控制器是数字的，每 `dt` 算一次

**必须写出来**
- `day2_state_space.py`
  - 单摆的 A/B/C/D
  - 前向欧拉 vs 精确离散化，对比 `dt` 大小对稳定性的影响

**验证**
- [x] `dt` 太大时前向欧拉发散（**和 W5 的 `Kd·dt < 2` 是同一个道理**）
- [x] 精确离散化在任何 `dt` 下都稳

**力扣**：94 二叉树的中序遍历（递归 + 迭代，迭代是重点）✅

> 📌 **完成情况（11/18 复盘）**：18 个数全对；`get_Ad_ZOH` 解析解一次写对。
> 🔴 两个指标口径问题：`int(10/0.3)=33` 只跑了 9.9 s（0.0918 是相位不是衰减）；
> 「末端 |θ|」不是振幅（全程峰值才是，ZOH 每行都 = 0.1）。
> 已补 `round()` + 峰值列 + `eig(Ad_ZOH)` 验证（模长恒 = 1）。

### Day 4 · 周四 11/19 · 🔑 C++ 工程化：建库骨架

**学**
- **为什么单文件不是工程**：不能给别人用、不能单独测、改一处全得重编
- **`include/` 放声明、`src/` 放实现** —— 这是 C/C++ 几十年的惯例
- **CMake 三件套**：`add_library` / `target_include_directories` / `target_link_libraries`

**必须写出来**
```
~/robotics/arm_control/
├── CMakeLists.txt
├── include/arm/
│   ├── pid.hpp
│   └── lowpass.hpp
├── src/
│   ├── pid.cpp
│   └── lowpass.cpp
├── tests/
│   ├── test_pid.cpp
│   └── test_lowpass.cpp
└── apps/
    └── demo.cpp
```

**关键要求：**
- `include/arm/pid.hpp` **只放声明**，**绝对不能有 `using namespace std;`**
- `CMakeLists.txt` 里编成**静态库** `libarm_control.a`
- `apps/demo.cpp` 链接这个库跑起来

**验证**
- [ ] `cmake .. && make` 零错误
- [ ] `./apps/demo` 跑出结果
