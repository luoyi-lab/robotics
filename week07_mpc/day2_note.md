# 首先了解cvxpy 是什么
cvxpy是一个专门解决数学优化问题的Python外挂

在MPC里，你每天都要问计算机一个问题：“我未来 N 步的油门该怎么踩，才能既最快到达终点，又最省电？”
这种问题在数学上叫凸优化问题（Convex Optimization）。如果你自己手写代码去算，需要写极其复杂的微积分和梯度下降算法；而用了 cvxpy，你只需要把数学公式原封不动地敲进去，它几毫秒就能给你算出完美答案。

简单介绍什么叫凸问题：
为什么叫“凸（Convex）”问题？
想象一下你在一口完美的圆底锅里放了一颗玻璃珠。
你从锅边缘的任何一个位置松开手，珠子最后都会滚到最底部的同一个点。
从几何形状上看，这个碗的内壁是向外“凸”出来的（像一个倒扣的 U 型，开口向上）。

数学上的定义：如果你在函数图像上随便取两个点连成一条直线，这条直线永远在函数图像的上方（或者重合）。在二维平面上，这就叫“凸函数”。

在 MPC 里，我们的代价函数（Cost）是误差的平方 (p−pref​)2
 。无论误差是正还是负，平方之后都是个正数。它的图像就是一条开口向上的抛物线（一个完美的碗）。

为什么工程界爱死它了？ 因为它绝对只有一个最低点（全局最优）。不管你的初始状态有多离谱，只要往下降，最终绝对能走到那个唯一的底部。而且，因为地形极其规则，计算机求导找底部的速度极快（毫秒级）。

有没有“凹（Concave）”问题？
有。但数学上有个有趣的性质：一个凹函数，只要加个负号，就变成了凸函数。
想象一个倒扣的碗（拱形）。如果你把珠子放在拱形的最高点，只要稍微有一点风，珠子就会滚下去，再也回不来。
凹函数的形状是开口向下（像一个倒 U）。如果在倒 U 的顶部，那是最高点（全局最大）。
在优化里：如果你要求一个函数的最大值，而它是个凹函数，这也叫凸优化问题（因为等价于求负函数的极小值）。
但是，如果你要求一个凹函数的最小值，那将是场灾难——因为没有底，它会一直掉到负无穷。

## cvxpy核心工作流
要解决一个最优化问题 只需要四步（四步法）
1.声明变量：x = cp.Variable() （告诉它：我要找的未知数叫 x）。
2.写目标函数：cp.Minimize(cp.square(x - 3)) （告诉它：我的目标是让 x 尽量靠近 3，也就是让 (x-3)² 最小）
3.写约束条件：constraints = [x <= 2] （告诉它：但是有个前提，x 不能超过 2）
4.求解：prob.solve() （告诉它：好了，我点完了，你去算吧）
算完之后，它会告诉你 x.value = 2.0。就这么简单

## cvxpy底层逻辑：超级包工头
cvxpy 自己其实不会算这道题。它是一个“包工头”
你把数学公式（上面四步）告诉 cvxpy，它会把你写的话翻译成底层求解器（比如 OSQP, SCS 等）能看懂的标准格式，然后把这些顶尖的数学家写的底层求解器叫过来帮你算。算完之后，它再把结果翻译回 Python 给你

## cvxpy的红线：只接“凸问题”
这是 cvxpy 最大的局限
它只接受能画成“一个碗”形状的问题（凸函数），比如求平方、求绝对值。这种问题永远只有一个最低点（全局最优）
如果你试图写 x * y （两个变量相乘），它凑不出一个“碗”，它就会直接报错 DCPError 并拒绝接单

## 为什么 MPC 离不开它？
MPC 的核心是“滚动优化”。在真实的机器人里，你每 0.01 秒（100Hz）就要重新预测未来 20 步，并在上千种可能的控制序列里找出最优的一组。如果用传统的 C++ 手动写优化算法太慢

但用了 cvxpy（或者其背后的工业级 C++ 求解器 OSQP），它能在微秒级别瞬间解算几百个变量。所以，cvxpy 就是让你能在 Python 里，用写数学公式的优雅方式，获得工业级极速求解能力的桥梁

# 第一部分 核心理论 从MPC到QP（二次规划）
day1写的predict： 回答的是会怎样
def predict(x0, U):     # 给定一串控制量，算出未来轨迹

今天要回答的是选哪串：
MPC的想法很朴素:要在一堆可能的U里面 挑一个最好的

怎么判别最好，就需要一个打分函数：目标函数：
J(U) = Σ_{k=0}^{N-1} [ (p[k] - p_ref)² · Q  +  a[k]² · R ]
                        └──────┬──────┘        └──┬──┘
                        离目标多远（越小越好）   用了多大力（越小越好）

(p[k] - p_ref)²   Q项   离目标有多远？ 误差越大 罚分越重
a[k]²             R项   用了多大力气 油门踩的越重 罚分越重

如果把前面的参数调大：
Q 调大：系统拼命追赶目标，误差小，但容易过冲、来回抖
R 调大：系统变成“懒汉”，为了省力宁愿慢慢走，导致跟得慢

为什么这一定是 QP
把 p[k] 展开 —— 记得 Day 1 的递推：
初始位置 p0=0，初始速度 v0=0
 
p1=1⋅p0+dt⋅v0+(dt²/2)⋅a0
​p2=1⋅p1+dt⋅v1+(dt²/2)⋅a1  
未来的位置 p 永远只是过去所有 a 的“一次方”相加  这就叫线性

p[k] = A 和 B 反复乘出来的东西，对 a[0..N-1] 是【线性的】

所以：
(p[k] - p_ref)²  →  线性表达式 的平方  →  二次型
a[k]²            →  二次型

求和之后：J = ½ UᵀHU + fᵀU + 常数        ← H 半正定
约束：     A·U ≤ b                        ← 线性     比如说电机物理极限：−0.2≤a≤0.2
二次目标 + 线性约束 = QP（二次规划）。 它有两个好性质：

有唯一全局最优（凸的），不会卡在局部极小
有成熟求解器，几毫秒就能解几百个变量

自己的思考这不就是二次函数求极值的问题吗 要求是凸，就是要找到极小值 线性约束就是给区间

# 第二部分 武器库 cvxpy四步法

import cvxpy as cp

1. 声明变量
x = cp.Variable()

2. 写目标（只说“最小化什么”）
objective = cp.Minimize(cp.square(x - 3))

3. 写约束（一个 list，可以有多条）
constraints = [x <= 2, x >= -5]

4. 求解 + 读结果
prob = cp.Problem(objective, constraints)
prob.solve()
print(prob.status)  # 'optimal'
print(x.value)      # 最优解
