### Day 1 · 周一 11/23 · MPC 是什么 + 一维小车建模

**学**
- **MPC 的三个核心**（缺一不可）：

  | 部件 | 干什么 | 没有它会怎样 |
  |---|---|---|
  | **预测模型** | 用 `A/B` 推未来 N 步 | 只能等出错才反应（= PID） |
  | **滚动优化** | 解一个最优化问题，取**第一步** | 会一次性算完 N 步然后全执行 |
  | **反馈校正** | 每拍用**实测状态**重新算 | 模型不准就一路错下去 |

- **预测时域 N / 控制时域 Nc**：N 是往前看多少步，Nc 是其中真正"下指令"的步数（`Nc ≤ N`）
- **一维小车**（本周的实验对象）：

  ```
  状态 x = [p, v]ᵀ    输入 u = 加速度 a

  连续： ṗ = v,  v̇ = a

  离散（双积分器的精确形式）：
      p[k+1] = p[k] + dt·v[k] + (dt²/2)·a[k]
      v[k+1] = v[k] + dt·a[k]

  A = [[1, dt], [0, 1]]      B = [[dt²/2], [dt]]
  ```

  > ⚠️ **`p[k+1]` 里那个 `dt²/2·a[k]` 不能丢。**
  > 只写 `p[k+1] = p[k] + dt·v[k]`（前向欧拉）的话，`B` 必须是 `[[0],[dt]]`，两个式子要配套。
  > 用 `dt²/2` 版本的 `B` 时，末位置会正好等于 `½·a·t²` —— 万有引力那套物理公式，方便对账。

- ⚠️ **注意这周的 A 和 W6 Day 2 的 A 不是一回事**：
  W6 的 A 是**连续系统**（`[[0,1],[-g/l,0]]`），这周的 A 是**已经离散好的**。
  `dt` 直接焊在矩阵里，所以 `A` 依赖采样周期。

**必须写出来**
- `week07_mpc/day1_mpc_model.py`
  - 建 `A`、`B`（`dt = 0.1`）
  - 写一个 `predict(x0, U)`：给定初始状态和一串输入 `U`（长度 N），**开环**推出 N 步轨迹
  - 画出来：同一个初始状态，三组不同输入下的轨迹（`a = 0` / `a = +1` / `a = -1`）

**验证**
- [ ] `predict` 的末状态和**手算**一致（给定 `x0=[0,0]`、`a=1`、`dt=0.1`、N=10，`p = 0.5`、`v = 1.0`）
      > 🔑 `p = 0.5` 正好等于 `½·a·t² = ½·1·(10×0.1)²` —— **和连续解的物理公式对上了**，
      > 说明你的离散化是对的。我这边实测 `p = 0.5000000000000001`、`v = 0.9999999999999999`。
- [ ] `a = 0` 时 `v` 恒定、`p` 线性增长

**力扣**：101 对称二叉树（递归 + 迭代）

### Day 2 · 周二 11/24 · QP 建模 + 求解器

**学**
- **MPC 的目标函数**（最朴素版本，只跟踪目标，不管约束）：

  ```
  min  Σ_{k=0}^{N-1} [ (p[k] - p_ref)² · Q  +  a[k]² · R ]
       └──┬──┘                        └──┬──┘
       跟踪误差的代价                 用力过猛的代价
  ```

  - `Q` 大 → 追得紧、但容易抖
  - `R` 大 → 平稳、但追得慢
  - **这就是 LQR 里那两个 Q/R，MPC 把它们搬进了滚动时域**

- **为什么是 QP（二次规划）**：目标函数是**二次型**（平方和），约束是**线性**的 ——
  这类问题的标准形式叫 QP，有成熟求解器，而且**有唯一全局最优**

  ```
  min  ½ xᵀHx + fᵀx
  s.t. lb ≤ Ax ≤ ub
  ```

- **`cvxpy` 的用法**：你只写数学式子，它负责变成 QP 交给 `osqp`

**必须写出来**
- `week07_mpc/day2_qp_basics.py`
  - 用 `cvxpy` 解一个**手算得出来**的小 QP，对账
  - 例：`min (x-3)² + (y-1)²`，`s.t. x + y ≤ 2` → 手算答案是 `(2, 0)`，程序必须一致
  - 再解一个带 `lb/ub`（box 约束）的，练习写约束

**验证**
- [ ] 手算答案和 `cvxpy` 解出来一致（误差 < 1e-6）
- [ ] 能说出 `problem.status` 为 `optimal` / `infeasible` 分别意味着什么

**力扣**：98 验证二叉搜索树（**中序遍历必须严格递增** —— 用你 94 写的迭代版）

### Day 3 · 周三 11/25 · 一维小车 MPC 闭环跑起来

**学**
- **滚动优化的循环长什么样**：

  ```
  每一拍：
    1. 读当前状态 x[k]（实测，不是预测的）
    2. 解 QP，得到未来 N 步的 a[0..N-1]
    3. 【只执行 a[0]】
    4. 世界往前走一步，拿到新的 x[k+1]
    5. 回到 1
  ```

  ⚠️ **第 3 步是 MPC 的灵魂**：算 N 步、只做 1 步、下一拍全部重算。
  **不然就叫"一次算完 N 步全执行"—— 那就退化成开环了。**

**必须写出来**
- `week07_mpc/day3_mpc_car.py`
  - 完整闭环 MPC：小车从 `p=0` 走到 `p_ref=10`
  - 加约束：`|a| ≤ 2`（加速度上限）
  - 打印每拍的实际位置和 `cvxpy` 解出来的第一步控制量

**验证**
- [ ] 小车收敛到 `p_ref`（误差 < 0.1），且 `|a|` 从不超 2
- [ ] **对比 N = 5 / 10 / 20**：N 越大，超调越小但每拍算得越慢（打印求解耗时）
- [ ] **对比有约束 vs 无约束**：无约束时 `|a|` 会超过 2
- [ ] 把 `p_ref` 中途改一次（比如第 50 拍时改成 0），小车能跟着换目标

### Day 5 · 周五 11/27 · C++ 运动学重写（二）：和 Python 对账

**学**
- **"对账"是什么意思**：同一个输入，两个实现（Python / C++）给出**同一个数**（误差 < 1e-9）
- 这是**跨语言移植唯一可靠的验收方式** —— 不是"看起来一样"，是"数一样"

**必须写出来**
- `week07_mpc/day5_fk_crosscheck.py` —— 生成 50 组随机 `(θ1, θ2, L1, L2)`，用 Python 的 `fk2link` 算末端，存成 `crosscheck.json`
- `week07_mpc/day5_fk_crosscheck.cpp` —— 读那个 json（或者干脆用 `printf` 输出 50 行 csv），算同一个，逐行比对

> 💡 **别引 JSON 库**。最简单的做法：Python 输出 `csv`（`theta1,theta2,L1,L2,x,y,z`），
> C++ 用 `std::ifstream` + `,` 分割读进来，算完比对。**能用 20 行解决就别引依赖。**

**验证**
- [ ] 50 组随机参数，C++ 和 Python 的最大误差 < 1e-9
- [ ] 故意改错 C++ 里一个符号（比如 `L1 → L2`），确认对账**会红** —— 证明这个对账是有效的

### Day 6 · 周六 11/28 · RL：PPO 的 clipped 目标函数

**学**
- **先补 W6 Day 7 那三处**（笔记里写错的）：
  1. 策略梯度输出的是**动作**，不是 PID 增益
  2. Model-free ≠ 不用懂机器人
  3. `(q, q̇)` 当状态是**假设**，不是事实
- **策略梯度的一句话版本**：`θ ← θ + α · ∇log π(a|s) · A(s,a)`
  - 采样一条轨迹 → 算每个动作的"好于平均多少"（优势 A）→ 好的多做、坏少做
- **PPO 解决什么**：策略梯度**步长太大会崩**。
  `ratio = π_new(a|s) / π_old(a|s)`
  ```
  clipped = clip(ratio, 1-ε, 1+ε)
  L = min( ratio · A ,  clipped · A )
  ```
  **`min` 的作用**：好处再大，也不让你一次改超过 ε（典型 0.2）

**必须写出来**
- `week07_mpc/day6_ppo.md` —— 用自己的话回答三个问题（每个 200 字以内）：
  1. 策略梯度的目标函数是什么？为什么直接对它有梯度？
  2. PPO 的 `ratio` 是什么？它衡量什么？
  3. `clip` 为什么能防止"一次性改太猛"？`min` 在里面起什么作用？

**验证**
- [ ] 能说出 `ratio = 1` 时，`L = A`（新旧策略一样）
- [ ] 能说出 `A > 0` 且 `ratio` 超过 `1+ε` 时，梯度为什么变成 0
