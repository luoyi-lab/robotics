MPC的核心就是用模型推演未来N步，把所有可能的未来都算一遍 挑出最好的一步去执行

一句话区别：

                        靠什么	                               看多远
PID	                   当前误差	                             0（只看现在）
动力学前馈          当前状态 + 模型	                          0（只算当前）
MPC	            当前状态 + 模型 + 最优化	                   未来 N 步


# 第一部分 理论解析 为什么MPC比PID强
## 1. MPC 的三个核心（缺一不可）

预测模型：你必须得懂物理定律（比如状态空间方程x[k+1]=A⋅x[k] + B⋅u[k]   A 和 B 矩阵）。没它，就退化成瞎猜的 PID
x（状态）：小车的“简历”，包含位置 p 和速度 v等
u（输入）：你给小车踩的油门（加速度a）
A 矩阵：系统的“自然演化”（没有外力时，它自己怎么动）
B 矩阵：系统的“受控响应”（你踩油门后，它怎么动）

滚动优化：每次往后看 N 步，算出一个最优解（比如我要先加速，然后刹车）。但只执行第一步。为什么？因为现实有误差，算太远没用
而且如果一次算完 N 步全执行 → 变成开环，模型一错就完蛋

反馈校正：走完第一步后，传感器测一下实际位置。拿实际位置重新算一遍接下来的 N 步。永远在根据实际情况修正

## 2. 两个时域（N 和 Nc）

N（预测时域）：你要往前看多远。比如看未来 20 步（N=20）。

Nc（控制时域）：你要在这 20 步里，给多少步下发动作。通常Nc≤N。

为什么要有 Nc：如果 N=20，你要解 20 个控制量。但通常假设「第 Nc 步之后输入保持不变」，
问题规模就能从 20 个变量降到 Nc 个。这周先取 Nc = N，简单。

如果 Nc=10，意味着你只优化前 10 个控制量，后 10 步假设输入保持第 10 个不变。解完之后仍然只发第一步

# 第二部分 一维小车建模 数学变成代码
这是本周全部的实验对象 —— 一个只能沿一条直线走的小车

状态  x = [p, v]ᵀ        p = 位置，v = 速度
输入  u = a               加速度（这就是你要"控制"的量）

物理公式与离散化：

连续方程（牛顿第二定律）：
ṗ = v
v̇ = a

离散化（dt是采样周期）：
p[k+1] = p[k] + dt·v[k] + (dt²/2)·a[k]      匀加速直线运动公式
v[k+1] = v[k] + dt·a[k]                     当前速度 + 加速度乘时间 = 新速度

写成矩阵如下： x = [p, v]ᵀ （自己推导）
A = [[1, dt],
     [0,  1]]

B = [[dt²/2],
     [ dt  ]]

x[k+1] = A @ x[k] + B * a[k]
