## 设计取舍

### FK 用两种独立方法实现并互相验证

- **几何推导** —— `x = L1·cosθ1 + L2·cos(θ1+θ2)`：直观，但只适用于平面两连杆
- **齐次变换** —— `T = Rz(θ1)·Trans(L1)·Rz(θ2)·Trans(L2)`：通用，代价是不直观
- 后者是 **完整 D-H 在 α=0、d=0 时的特例**（W4 已验证：两者位级别相同）

### IK 用解析解而不是迭代

两连杆的 IK 有闭式解，不需要数值迭代：

```
c2 = (x² + y² - L1² - L2²) / (2·L1·L2)
s2 = ±√(1 - c2²)          ← 正负号 = 两个解（肘上 / 肘下）
θ2 = atan2(s2, c2)
θ1 = atan2(y, x) - atan2(L2·s2, L1 + L2·c2)
```

- **必须用 `atan2` 不能用 `arccos`**：`arccos` 只返回 `[0, π]`，丢掉符号信息，两个解会塌成一个
- `|c2| > 1` → 够不着，返回空
- 浮点误差会让边界点的 `c2` 略微超出 1（如 `1.0000000000000004`），要 **先带容差判断、再 `clip` 到 `[-1, 1]`**，否则 `sqrt` 会出 `nan`

### D-H 统一用标准型（2026-11-04 决定）

```
标准型：T_i = Rz(θ_i) · Tz(d_i) · Tx(a_i) · Rx(α_i)      参数下标都是 i
```

**不用改进型（Craig）**：`Rx(α_{i-1})·Tx(a_{i-1})·Rz(θ_i)·Tz(d_i)`

理由：
1. W3 的 `link_transform` 是它 `d=α=0` 的特例，能直接对账
2. 和 URDF 的 `<origin>` 对应更顺 —— **关节 `i+1` 的 origin 装的是第 `i` 行的参数**
3. 查资料、看论文，标准型更普遍

⚠️ **两套绝不能混用**：公式顺序和下标要同时改。只改一个的话，末端位置差将近 1 米，而**程序不报错** —— 它只是给出了一只根本不存在的机械臂。

## 踩过的坑

- **`θ2` 是相对角**（相对连杆 1），绝对角是 `θ1 + θ2` —— 写成 `θ2` 会算错但不报错
- **齐次变换里 `T[:3,3]` 的平移在父坐标系中表达** —— 要让连杆沿自身方向伸出 `L`，得先乘 `R`
- **PyBullet 的四元数是 `(x,y,z,w)`**，和标准公式的 `(w,x,y,z)` 差一位
- **PyBullet 内部是 float32**，精度 ~1e-7，对账容差要用 `1e-6` 而不是 `1e-9`
- **`getLinkState` 返回的 `[0][1]` 是质心、`[4][5]` 才是 link 坐标系** —— 对账要用后者
- **`linkIndex` 不是「第几个 link」，是「第几个关节」**：`-1` = base_link
- **奇异位形有两种完全不同的表现**：`θ2 → 0`（伸直）是两个解**温和合并**；`θ2 → π`（折回）是 `θ1` **突然崩塌成乱数**
  - 后者只在 `L1 = L2` 时发生 —— 因为那时 `k1 = L1 + L2·cos(π) = 0`，IK 公式出现 `atan2(0,0)`
  - 但 `det(J) = 0` **跟 `L1/L2` 无关**，`θ2 = 0` 或 `π` 都是奇异
- **「对账能过」只能证明内部自洽** —— 用同一张表算两边，符号写错也照样过。**要么用外部实现验证，要么故意改坏看它会不会失败**
