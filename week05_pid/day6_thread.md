多线程要记住的东西
# 一、 真正要“学懂”的3个思维模型（不用背代码）
你要带走的不是语法，而是在什么场景下用什么工具的判断力：

为什么要多线程？
传感器读得太快（比如 1000Hz），PID 算得没这么快（500Hz）。不能让 PID 拖累传感器，所以必须分家，一人开一个 std::thread。

什么是数据竞争？
两个线程同时去 ++p，会导致数据丢失。因为 ++p 在底层是“读-改-写”三步，中间被插队就会覆盖。

怎么解决？（重点考点）
简单变量（如 double、int）：无脑用 std::atomic，极快、极安全。
复杂逻辑或大结构体：用 std::mutex 加锁，强行排队。
绝对不锁的东西：线程内部的局部变量（比如 PID pid）。这是线程的私有财产，别人碰不到，加锁纯属浪费 CPU。

# 二、 真正需要“能默写”的骨架代码（极简版）
考试或写项目时，只要把这十几行背下来，遇到多线程直接套，绝对没问题。

骨架 1：如何开两个线程并等待它们干完？

#include <thread>

// 干活的任务函数
void my_task() { /* 你的代码 */ }

int main() {
    // 1. 创建两个小弟
    std::thread t1(my_task);
    std::thread t2(my_task);
    
    // 2. 告诉主程序：必须等他们干完，你再退出
    t1.join();
    t2.join();
    return 0;
}

骨架 2：如何安全地保护共享变量？

#include <atomic>
#include <mutex>

std::atomic<int> shared_int{0}; // 方式 1：原子变量，极快，不用管括号
std::mutex mtx;
double shared_double = 0.0;

// 方式 2：互斥锁
void safe_add() {
    std::lock_guard<std::mutex> lock(mtx); // 只要写了这句，大括号内绝对安全
    shared_double += 1.0;
}

# 三、 面试官或导师会怎么考？
他们绝对不会让你手写 200 万次循环。
他们只会问你一句话：“你看这段代码，哪里需要加锁？”

你只要回答出下面这两点，就是满分：

“共享的 sensor_value 被两个线程同时读写，必须加 atomic 保护
但是 PID pid 定义在控制线程内部，是私有变量，绝对不能加锁，否则会严重拖慢性能。”
